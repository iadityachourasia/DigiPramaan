# Page 10 — Reports & Profile

> See `00-README.md` for the Status Model, Role Permission Matrix, and Fixed
> Vocabulary this file assumes. Fixed in this revision: filter now
> references "Compliance Status" explicitly (Pending/Compliant/
> Non-Compliant/Needs Review) rather than an unlabeled "status" filter.

## 1. Purpose & Why It Matters

The PS explicitly requires "generation of digital compliance reports in PDF
and editable formats" — note "and," not "or." A PDF-only export is a common
shortcut that technically under-delivers against the PS text.

## 2. Sections & Fields

### Report Builder
- Filters: date range, category, Compliance Status, manufacturer, region,
  source
- Report scope selector: single record (pre-filled if arriving from
  Product Compliance Detail or Manufacturer Scorecard) vs. a filtered set
  from Compliance Records

### Format Selection
- PDF (fixed, official-looking layout, suitable for printing/filing)
- Editable format — Word (.docx) and/or Excel (.xlsx), explicitly
  satisfying the PS's "PDF and editable formats" requirement rather than
  defaulting to PDF-only

### Generate Report
- Submit action with a visible generation-progress state

### Download History
- Previously generated reports: name/scope, format, generated date,
  generated by, re-download action

### Profile
- Name, email/username, role (Enforcement Officer / Admin / Reviewer),
  department

### Settings
- Password change / session preferences
- Notification settings (if backend supports)

### Logout

## 3. User Flow

1. User arrives either via direct navigation or pre-filled from another
   page ("Generate Report" from Product Compliance Detail)
2. User confirms or adjusts the report scope/filters
3. User selects one or more output formats
4. User clicks Generate, sees progress, then a completion state with
   download links
5. Report appears in Download History for future re-download without
   regenerating

## 4. States & Edge Cases

| State | What the user sees |
|---|---|
| Report scope matches zero records | Blocked from generating with a clear message |
| Generation in progress | Visible progress indicator, page remains usable |
| Generation failure | Clear error with Retry, filters/scope preserved |
| Very large report scope | A size/row-count warning before generation |
| Download history empty (first use) | "No reports generated yet" message |

## 5. UX4G / Design Notes

- Format selection (PDF vs. editable) is a clear multi-select or distinct
  toggle, not implied by a filename extension after the fact.
- Progress and completion states reuse the same status/progress visual
  pattern as the Scan/Upload page.
- Profile/Settings can be visually lower-priority in layout than the
  Report Builder.

## 6. Definition of Done

- [ ] Both PDF and at least one editable format are genuinely selectable
- [ ] Zero-record report scope is blocked with a clear message
- [ ] Download history persists and supports re-download without
      regeneration
- [ ] Progress/completion pattern reuses the same visual language as the
      Scan/Upload page's status treatment
- [ ] Status filter uses "Compliance Status" with the fixed 4-value
      vocabulary, not a generic unlabeled filter

## 7. Claude Design Prompt

```
Build the Reports & Profile page inside our existing app shell.

Reuse existing components: Input, Select, Button, Table (for download
history), Card. Reuse the same status/progress visual pattern from the
Scan/Upload page for report generation states — don't invent a new pattern.

Sections needed:
- Report builder: filters for date range, category, Compliance Status
  (Pending/Compliant/Non-Compliant/Needs Review), manufacturer, region,
  source; a scope selector for single record vs filtered set from
  Compliance Records (pre-fillable when arriving from another page's
  "Generate Report" action)
- Format selection: PDF and at least one editable format (Word .docx or
  Excel .xlsx) — both must be genuinely selectable options
- Generate action with a visible progress state during generation
- Download history: table of previously generated reports — name/scope,
  format, generated date, generated by, re-download action
- Profile section: name, email/username, role, department
- Settings: password/session preferences, notification settings
- Logout action

States to implement explicitly:
1. Report scope matches zero records — block generation with a clear
   message, don't produce an empty file
2. Generation in progress — visible progress indicator, rest of page stays
   usable
3. Generation failure — clear error, Retry action, preserve the user's
   scope/filter selections
4. Very large report scope — a size/row-count warning shown before
   generation begins
5. Empty download history (first use) — "No reports generated yet" message

Check this against our design system rules before finalizing and flag
anything that couldn't fully comply instead of approximating it.
```
